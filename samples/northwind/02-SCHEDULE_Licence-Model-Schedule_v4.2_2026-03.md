1. Definitions

A) "**Access**" means to interact with the Software directly or indirectly,
through any interface, including a user interface, an application programming
interface, a command line, a report, an extract, a scheduled job, or any
intermediary program, device or system.

B) "**Core**" means a single physical or virtual processing core available to
the operating system on which an Instance runs. Where a Server presents
hyper-threaded logical processors, each two logical processors count as one
Core, rounded up to the next whole Core.

C) "**CPU**" means a single central processing unit (a single processing core).

D) "**Device**" means a single physical or virtual workstation, terminal,
handheld unit, kiosk or multi-function peripheral from which the Software is
Accessed.

E) "**Development Use**" means use of the Software by a Named Developer solely
to design, build and unit-test applications, and does not include any use which
supports a production business process.

F) "**Managed Volume**" means the volume of data under management by the
Software, measured in terabytes at the point of highest usage in a calendar
quarter.

G) "**Named User**" means (a) an individual natural person, or (b) a user
identity, account or credential in the Software or in an external directory or
identity provider, in either case with Access to the Software. A Named User
identity may not be shared between two or more individual natural persons.

H) "**Non-Production Use**" means use of the Software where the functionality of
the Software is not placed into production use and use is restricted to system
testing, quality assurance, development, training, demonstration, backup,
failover, hot standby or cold standby purposes. Non-Production Use does not
include load balancing, or any other system configuration whereby the Instance
proactively supports production workload.

I) "**Page Processed**" means a single side of a single sheet, or its electronic
equivalent, rendered, converted, composed, captured or output by the Software.

J) "**Program Instance**" means a single copy of the Software installed onto a
single Server, identified by a distinct licence key.

K) "**Session**" means a connection between a Device or Named User and an
Instance which remains open, whether or not activity occurs, until it is closed
or terminated.

L) "**Transaction**" means a single instance of any document, writing or record
created, adapted, transformed or processed by the Software, and shall include
any report, facsimile, text message, data sheet, file, index, financial
statement, invoice, credit note, statement of account, remittance advice,
ticket, expense record, payroll record, order, delivery note, income tax return,
receipt, deposit slip, banking record or time slip, the data for which is input
to, output from, created, processed, or manipulated in some way by, the
Software.

M) "**Work Unit**" means a unit of computational capacity as measured by the
Software's own metering function and recorded in the usage report.

2. General Licence Types

Each Licence Model in Sections 4 to 15 is a standard production Licence Model
unless a Transaction Document identifies one of the following general licence
types, in which case the terms below modify the applicable standard production
Licence Model as stated.

2.1. A. Non-Production Licences

The applicable standard production Licence Model, except that the functionality
within the Software is not placed into production use and use of the Software is
restricted to system testing, development, training, backup, failover, hot
standby or cold standby purposes. This does not include load balancing or other
system configurations whereby other system resources proactively support
production use.

2.2. B. Evaluation Licences

The applicable standard production Licence Model, except that (unless the
parties otherwise agree in a Transaction Document): (i) the Software Licence
expires thirty (30) days after delivery; (ii) the Software may not be used to
process production data; (iii) no Support Services are provided; and (iv) the
warranty in Section 9.1 of the EULA does not apply and the Software is provided
"as is".

2.3. C. Read Only Licences

The applicable standard production Licence Model, except that: (i) an individual
allocated this Software Licence may view, query and export data from the
Software, but may not create, amend, approve, delete or otherwise modify any
record in the Software; (ii) the generation of a report, extract or dashboard
does not constitute modification, provided the output is not written back to the
Software; and (iii) where an individual performs any action reserved to a full
licence, Licensee shall be deemed to have acquired the applicable full Software
Licence for that individual as of the date of that action.

2.4. D. Runtime Licences

The applicable standard production Licence Model, except that the Software may
be used only in support of a single application identified in the Transaction
Document, and may not be used to develop, extend or support any other
application.

2.5. E. Disaster Recovery Licences

The applicable standard production Licence Model, except that: (i) a cold
standby Instance, which is installed but not running and holds no synchronised
data, requires no Software Licence; (ii) a warm standby Instance, which is
running and receives synchronised data but serves no workload, requires Software
Licences equal to fifty per cent (50%) of the production quantity; (iii) a hot
standby Instance, which is running, receives synchronised data and is capable of
serving workload without manual intervention, requires Software Licences equal
to the full production quantity; and (iv) following a disaster event Licensee
may operate a standby Instance at production capacity for up to thirty (30)
consecutive days without additional Software Licences, provided Licensee
notifies NDS in writing within five (5) Business Days of the event.

original individual leaves Licensee's organisation, or moves to a position in
which that individual will no longer use the Software, provided that (a) the
original individual's Access is first revoked, and (b) the re-allocation is

(vii) Licensee must maintain a permanent record of user account allocations and

(iv) Licensee is required to maintain a record of all individuals allocated an

5. Concurrent User Licence Models

5.1. A. Standard Concurrent User Licence Model

(i) Licensee must purchase a Software Licence for each concurrent Session open
against an Instance, measured as the maximum number of Sessions open
simultaneously at any point during the measurement period.

(ii) A Standard Concurrent User licence key is permanent to a particular Server
or Program Instance. Standard Concurrent User licence keys cannot be dynamically
or otherwise re-allocated to other systems. A Standard Concurrent User licence
key may only be re-allocated to a replacement Server if the original Server is
taken out of service.

(iii) In the case of multiple Program Instances, the quantity of Standard
Concurrent User licence keys summed across all Program Instances must not exceed
the quantity of Standard Concurrent User licences.

(iv) A Session which remains open without user activity for more than thirty
(30) minutes is not counted, provided the Software is configured to terminate
idle Sessions at or below that threshold.

5.2. B. Standard Anonymous User Licence Model

The terms, conditions and limitations applicable to the use of Software licensed
under the Standard Anonymous User Licence Model are identical to those that
apply to Software licensed under the Standard Concurrent User Licence Model
except that:

(i) Licensee may allocate Software Licences to any individual and is not
required to identify those individuals.

(ii) This Licence Model may be used only for Access from a public-facing
interface, and may not be used to provide Access to Licensee's own employees or
contractors.

7.1. A. Production CPU Licence Model

(i) Software licensed under this Licence Model is licensed per CPU, per
Instance, per Deployment Type.

(ii) Licensee must licence every CPU available to the operating system on which
the Instance runs, whether or not the Software uses that CPU, unless the
Software is constrained to a defined subset of CPUs by a hard partitioning

(iii) A minimum of four (4) CPUs must be licensed per Instance.

7.2. B. Production Logical CPU Licence Model

The terms applicable to the Production CPU Licence Model, except that a licence
is required for each logical processor presented to the operating system rather
than for each Core.

7.3. C. Platform Core Licence Model

(i) Software licensed under this Licence Model is licensed per Core across all
Instances of the Software operated by Licensee.

(ii) Cores may be aggregated across Instances of the same Software product and
the same Deployment Type, and only across those.

10. Volume and Capacity Licence Models

10.1. A. Managed Volume Licence Model

(i) Software licensed under this Licence Model is licensed by Managed Volume.

(ii) Data held solely in backup or archive media which is not available to the
Software for query is excluded from the measurement.

(iii) Managed Volume is measured at the point of highest usage in each calendar
quarter and is not averaged across quarters.

10.2. B. Pages Processed Per Year Licence Model

(i) Software licensed under this Licence Model is licensed by the number of
Pages Processed by the Software in each calendar year.

(ii) The count resets on 1 January of each calendar year. Unused volume does not
carry forward.

10.3. C. Electronic Employee Files Licence Model

(i) Software licensed under this Licence Model is licensed by the number of
individual employee records held in the Software.

(ii) The count is taken at the point of highest usage in each calendar year and
includes records of former employees which have not been deleted.

11. Transaction Licence Models

11.1. A. Perpetual Transaction Licence Model

(i) Software licensed under this Licence Model is licensed by the number of
Transactions processed by the Software in each calendar year.

(ii) The Transaction count resets on 1 January of each calendar year. Unused
Transaction volume does not carry forward.

(iii) Where Licensee processes Transactions in excess of the licensed volume,
Section 3.2 applies and the excess is chargeable at NDS's then-current list
price for the applicable Transaction band.

(iv) A single document processed through two or more distinct Software
components counts as one Transaction, provided the processing occurs within a
single workflow instance.

(v) The Software Licences may not be allocated to any other party.

11.2. B. Term Transaction Licence Model

The terms applicable to the Perpetual Transaction Licence Model, except that the
Software Licence expires at the end of the term stated in the Transaction
Document and no right to continued use survives expiry.
